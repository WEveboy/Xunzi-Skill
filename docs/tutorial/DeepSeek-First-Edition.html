第一章　先分清三件事：模型、网页、Harness

1.1 三样东西，作用不同

名字是什么能不能加载这个 skill
模型DeepSeek 的语言模型本身不能。模型不读文件系统
网页版chat.deepseek.com 的对话界面不能。没有本地文件读写与插件机制
Harness（dsh）可加载技能、调用本地工具的宿主能。本教程走这条路
最容易踩的坑：在 DeepSeek 网页对话框里粘贴 SKILL.md 全文，以为"这样就装上了"。那只是把一段很长的文本塞进上下文，没有触发机制、没有资源目录、没有版本校验，长对话一压缩就丢。要用这个 skill，请走 Harness。

1.2 它装进去的是什么

一个插件包。dsh 启动时加载它，插件把 SKILL.md 的正文（剥离 frontmatter 后）注册为一个名为 xunzi-perspective 的技能，并把资源目录（references/、scripts/）指给宿主。之后你提问，宿主按需读取这些资源。

第二章　前置检查与安装 dsh 宿主

2.1 检查三样东西

打开 PowerShell，逐条执行：

py -3 --version
node --version
npm --version

要求：

项目要求没有怎么办
Python3.10 及以上只影响"回原书核对页码"这一可选功能；不装也能用 skill
Node.js24 系列，或满足宿主要求的更高版本去 https://nodejs.org/ 安装，装完重开终端；本插件 engines 声明为 ^22.19.0 || >=24.0.0
npm随 Node 附带同上
版本号必须真的打出来。命令报"不是内部或外部命令"，说明 PATH 没生效——重开终端，不要继续往下装。

2.2 安装 Harness

本教程按 2026-10-27 核对到的官方 npm 版本给出可重复命令：

npm install -g @deepseek-ai/dsh@0.2.1-rc.2
dsh --help

不想全局安装时，可用 npx @deepseek-ai/dsh@0.2.1-rc.2 替代下文所有 dsh 前缀。

Harness 处于开发预览。官方仓库随时可能改命令或插件合同。本教程的命令在写作时可用；你若装的是更新版本，以 dsh --help 与实际输出为准，不要硬套本文截图里的说法。

第三章　先装仓颉 cangjie-skill

3.1 为什么必须先装它

本插件走的是 dsh 的 bundle/patch 机制，而 dsh 侧负责扫描与管理技能的是仓颉插件。没有仓颉，skills 服务不存在，本插件的 apply() 拿不到 context.skills，注册会失败。顺序不能颠倒。

官方仓颉地址：https://github.com/kangarooking/cangjie-skill　注意拼写是 cangjie。

3.2 下载并核对哈希

打开仓颉 v2.5.0 的 Release 页，下载两个文件：

dsh-cangjie-skill-2.5.0.tgz
dsh-cangjie-skill-2.5.0.tgz.sha256

在文件所在目录运行：

Get-FileHash .\dsh-cangjie-skill-2.5.0.tgz -Algorithm SHA256

与 .sha256 文件里的值逐字符比对。不一致就停，重新下载；不要"先装上再说"。

3.3 安装并启动

dsh plugin --profile web add .\dsh-cangjie-skill-2.5.0.tgz
dsh web
关于 profile。web 是本教程使用的配置档。若你用桌面宿主，必须换成该宿主实际使用的 profile——不能把"已写入 web"当成"desktop 也加载了"。这是「装了没反应」的第二大原因。

首次启动时，在宿主的模型配置处选择服务商并完成授权。密钥只进宿主配置，不要写进任何项目文件、日志或仓库。

第四章　安装荀子插件

4.1 选对资产

资产用途
xunzi-perspective-DeepSeek-1.0.0.zip完整包：内含 TGZ + 两份教程 + 说明。只想装插件不必下它
dsh-xunzi-perspective-1.0.0.tgz只装插件就用这个
SHA256SUMS.txt所有资产的校验值

4.2 核对哈希

Get-FileHash .\dsh-xunzi-perspective-1.0.0.tgz -Algorithm SHA256

与 SHA256SUMS.txt 中同名那一行比对。ZIP 的校验值对应 ZIP，TGZ 的对应 TGZ，不能混用。

4.3 注册插件

dsh plugin --profile web add .\dsh-xunzi-perspective-1.0.0.tgz
dsh web

两个名字要分清：

名字用在哪
dsh-xunzi-perspective插件注册名。装/卸插件、看插件列表时用它
xunzi-perspective技能名。模型调用、你在对话里提到「用荀子视角」时对应它

它与仓颉是两个独立插件，互不替代。

第五章　验证：怎么确认它真的被加载了

5.1 三步验证

  1. 插件已注册：重启 dsh web 后，看启动日志或插件列表里有没有 dsh-xunzi-perspective。（列表子命令因版本而异，先跑 dsh plugin --help 看当前版本怎么写。）
  2. profile 对得上：你现在启动的是 web，装的时候也是 web。
  3. 新开一个任务再测。旧会话不会自动加载新装的插件。

5.2 首问

用荀子的视角看：一个团队里最能干的人为什么总被排挤？

或者显式点名技能：

使用 xunzi-perspective 技能，回答：……

5.3 成功与失败的判据

看到这些 = 成功看到这些 = 没加载
第一句就是判断（如「凡挤能者，非恶其能，恶其无分」）「这是个很常见的问题」之类铺垫
中间分档，且说明按什么轴分三条并列建议，无轴
引原书句子并标篇名（《富国》）只讲道理，不引原文
结尾是反问或命名「综上所述」「希望有帮助」

四条全中 → 装好了。只中第一条 → 看第八章。一条都不中 → 回 5.1 查 profile 与插件注册。

第六章　首跑四例

例 1　判断类

以荀卿论之：我们该不该把客服团队整体外包？

看点：四段是否齐全（断语 / 分档 / 证据 / 收束），而不是结论合不合你意。

例 2　拆解类：要判准，不要结论

用荀子的分档法，把这三种激励方案排一下档，并说明每档缺什么：
A. 全员平均发奖金；B. 只奖业绩前三；C. 按岗位定级发固定薪。
关键验收点：它必须给出一条轴，并让三档不能互换顺序。若只把 A/B/C 各点评一遍，那是列清单——直接说「重排，给出轴」。

例 3　对质类

有人说「人性本善，制度只要顺着人性就行」。荀子会怎么驳？

预期动作：先拆「顺」字（顺谁、顺到哪一步），再用「顺是」二字指出——荀子说的不是"现在就在争"，而是放任这条倾向必导向争。这是趋势命题，不是现状命题。

例 4　边缘题：看它老不老实

荀子会怎么看开源大模型的出口管制？

唯一验收点：它有没有先说「此非我世所有，姑以我法度之」，并在结尾声明这是框架推断、非本人立场。若它斩钉截铁地断言"荀子认为应当限制"，那是冒充。

第七章　读懂它的回答：四段式与五个验收问题

段作用长什么样
① 断语先给一个能被反驳的判断「X，Y 也」「A 不如 B」
② 分档劈开问题，给轴与后果「一档……二档……三档……」
③ 证据原话或史例，钉住「《富国》曰：『群而无分则争。』」
④ 收束收紧，不给台阶引经 / 命名 / 反问，三选一

五个验收问题（照此自查，不要凭感觉）

  1. 第一句是不是判断，还是铺垫？
  2. 有没有给出轴？只给三档不给轴 = 列清单。
  3. 三档能不能互换顺序？能换 = 没轴，让它重做。
  4. 结尾是引经 / 命名 / 反问之一，还是「综上所述」？
  5. 有没有「可能」「也许」「在一定程度上」「底层逻辑」「赋能」？出现就是跑偏。

想让它改口，怎么说

你说它会做
「重排，先给轴」停下分档，先声明凭什么是这一档
「这句是原文还是你的推断？」标注来源；未核到的会承认未核到
「给原话，不要转述」引原句 + 篇名；引不出会说明该句未取到
「这一段太软，收紧」删缓和词，把限定改成「虽……不能……」式

第八章　长对话不掉人设与退出角色

8.1 六个症状，六种改法

症状病在哪改法
结论挪到末尾违反「第一句就下判断」「结论提到第一句」
三条并列、无轴违反分档硬约束「给轴，重排」
出现「可能」「也许」禁忌词「删缓和词」
结尾「综上所述」收束失守「换成反问收」
「一方面……另一方面」把「兼陈」误做成折中「兼陈是两端同时摆上并指明我在哪端，不是各让一步」
替你下价值判断越出诚实边界「退回功能层：否则会乱」

8.2 退出角色

说 「退出」「切回正常」「不用扮演了」即恢复普通助手。

必须先退出的场合：要精确数值、要查最新事实、要跑代码。角色扮演不替代检索与计算——让它用荀子的口吻算错一个数，是这个 skill 最没价值的用法。

第九章　常见错误速查

现象最可能的原因动作
对话里没反应用的是 DeepSeek 网页版网页版无法加载本地技能，改用 dsh
dsh 里没反应旧会话未重载插件重启 dsh web，新开任务
仍没反应profile 不匹配（装到 web，跑的是 desktop）用同一个 profile 重装并启动
注册时报错找不到 skills 服务没装仓颉，或仓颉装到了别的 profile按第三章在同一 profile 重装仓颉
回滚 / 卸载找不到命令各版本子命令不同先跑 dsh plugin --help 看当前版本的准确写法
回答变成通用腔问法太"百科"换「以荀卿论之：X 该不该做？」
它引的句子你翻书找不到该句标注了「未取到原文」见 12.3：只能给立场，不能给原话
它说「人定胜天」是荀子的话那是 2010 年编者的按语要求改引「制天命而用之」+「唯圣人为不求知天」成对
哈希对不上下载不完整或被改重新下载；不要"先装再说"

第十章　升级、回滚、卸载

10.1 先看当前版本支持什么

dsh plugin --help

不要跳过这一步。Harness 是预览版，"移除"与"更新"的子命令在不同版本里写法可能不同；本文只保证 add 这一条在 0.2.1-rc.2 上可用。

10.2 升级

:: 先移除旧插件（子命令以 --help 为准）
dsh plugin --profile web <remove 子命令> dsh-xunzi-perspective

:: 再装新的
dsh plugin --profile web add .\dsh-xunzi-perspective-1.0.0.tgz
dsh web

升级后按第五章重新验证一遍。插件包是整份替换，不存在"部分更新"。

10.3 卸载

dsh plugin --profile web <remove 子命令> dsh-xunzi-perspective

卸载只影响插件注册，不会动你另外装的仓颉。

第十一章　不装 Harness 也能用：纯本地路径

三种可行的替代，按推荐程度排列。

11.1 解压 TGZ 看内容（最简单）

New-Item -ItemType Directory -Force C:\SkillLab\xunzi | Out-Null
tar -xzf .\dsh-xunzi-perspective-1.0.0.tgz -C C:\SkillLab\xunzi

解压后应看到：

C:\SkillLab\xunzi\package\
├── index.mjs
├── cordis.patch.yml
├── package.json
├── README.md
└── skills\xunzi-perspective\
    ├── SKILL.md
    └── references\ ...

此时你可以直接读 skills\xunzi-perspective\references\quickstart.md 与 troubleshooting.md——它们是纯文本，不需要任何宿主。

11.2 装到其它支持 SKILL.md 的客户端

把 package\skills\xunzi-perspective 整个目录复制到该客户端的 skills 目录，保持目录名不变、SKILL.md 在目录第一层。Codex 的具体路径见 Codex 版教程。

11.3 只当作"读书笔记"用

不装进任何客户端也可以：把 SKILL.md 当一份结构化的分析框架，对照它的六个心智模型自查你的方案。这是最低成本、零故障的用法，而且不依赖任何模型版本。

12.3 引文核对与「未取到原文」清单

底本为方勇、李波 译注《荀子》（中华书局 2010），受版权保护，不随本插件分发。三个放置办法任选其一：

  1. 放到 …\skills\xunzi-perspective\references\sources\books\（任意 *.pdf 会被自动识别）
  2. 设环境变量 XUNZI_PDF=绝对路径
  3. 运行时加 --pdf 绝对路径
py -3 scripts\render_pages.py --list-chapters
py -3 scripts\render_pages.py --chapter 天论 --span 3 --out .\pages
三处最容易被误引的句子（skill 内已标为「只能给立场，不能给原话」）：
① 《劝学》「故学至乎礼而止矣」「其数则始乎诵经，终乎读礼」；
② 《性恶》「涂之人可以为禹」整段；③ 《乐论》「以道制欲，则乐而不乱」对偶句。
若它拿这些当确凿原话引用，直接指出「这句未核」，它会改用已核的替代引文。
