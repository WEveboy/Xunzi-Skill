# 快速上手（随 skill 分发）

装好之后照着做，五分钟内看到第一次可用输出。

## 1. 确认装在哪

skill 目录长这样：

```
<skill根>/xunzi-perspective/
├── SKILL.md              ← 入口，frontmatter 里 name: xunzi-perspective
├── README.md
├── references/
│   ├── quickstart.md     ← 本文件
│   ├── troubleshooting.md
│   └── research/         ← 7 份调研记录（引用的原文都在这里，带书页）
└── scripts/render_pages.py
```

不同客户端的默认放置位置：

| 客户端 | 默认目录 |
|---|---|
| Codex | `~/.codex/skills/xunzi-perspective`（旧布局）或 `~/.agents/skills/xunzi-perspective`（新布局） |
| DeepSeek Harness（dsh） | 由插件包 `dsh-xunzi-perspective` 注册，不落地到 skills 目录 |
| 其他支持 `SKILL.md` 的客户端 | 该客户端的 skills 目录，保持目录名 `xunzi-perspective` |

## 2. 确认加载成功

新开一个任务（**不要**在安装它的同一个会话里测，多数客户端只在启动时扫描 skills），然后说：

```
用荀子的视角看：一个团队里最能干的人为什么总被排挤？
```

成功的标志是三条同时出现：

1. 第一句就是判断，不是「这个问题很复杂」；
2. 中间出现分档或分层（一档/二档，或「某者……某者……」）；
3. 结尾是引经、命名或反问，**没有**「综上所述」「希望对你有帮助」。

只出现第 1 条、后面变回通用助手腔 → 见 troubleshooting 的「跑偏」一节。

## 3. 三种问法

**A. 判断类（最常用）**

```
以荀卿论之：我们该不该把客服团队外包？
```

**B. 拆解类（要它给判准，不要结论）**

```
用荀子的分档法，把这三种激励方案排一下档，并说明每档缺什么。
```

**C. 对质类（用它驳一个说法）**

```
有人说「人性本善，制度只要顺着人性就行」。荀子会怎么驳？
```

不推荐的问法：「荀子关于管理的十个观点」（会退化成百科罗列，丢掉他的论证动作）。

## 4. 它会怎么答

固定四段：

1. **断语**——一句，能被反驳；
2. **分层/分档**——每档给出轴、缺失项、后果；
3. **证据**——原话级引文（标篇名），或一件史例、一个工艺类比；
4. **收束**——引经 / 命名 / 反问三选一。

如果一个回答把结论放在最后、中间是并列三条建议、结尾是总结段，那不是这个 skill 的输出，是模型掉回了默认腔。

## 5. 退出角色

说「退出」「切回正常」「不用扮演了」，即可恢复普通助手。

需要精确数值、现代事实、代码执行时，**先退出角色再问**——角色扮演不替代检索与计算。

## 6. 想核对某句原文怎么办

调研记录里每条引文都带「书页 N」。要回到原书核对：

```bash
# 1) 看篇名对应的书页与 PDF 页
python scripts/render_pages.py --list-chapters

# 2) 渲染该页（底本需自备，见下）
python scripts/render_pages.py --chapter 天论 --span 2 --out ./pages
```

底本为方勇、李波 译注《荀子》（中华书局 2010）。**受版权保护，不随本 skill 分发**。三个放置办法任选其一：

- 放到 `<skill目录>/references/sources/books/` 下（任意 `*.pdf` 会被自动识别）
- 设环境变量 `XUNZI_PDF=<绝对路径>`
- 运行时加 `--pdf <绝对路径>`

页码换算：`pdf 页索引 = 书页 + 13`。版式是「原文页 → 注释+译文页」交替，**只取原文页**可省一半配额。

没有底本也能正常用：所有被引用的原文都已在 `references/research/` 里逐字抄录并标注书页。

## 7. 什么时候不该用它

- 需要精确数值、最新事实、真实计算 → 直接问，别套角色。
- 涉及公平、权利、分配正义的规范判断 → 这个 skill 会带荀子的等级化默认值（"分"以差等为正义），它自己在「诚实边界」里承认这是盲区。
- 想让它"证明"某个现代制度正当 → 它只能给功能性理由（否则会乱），给不出价值理由。

以上三条不是限制，是使用说明。越界使用会得到听起来很像、实际很空的话。
